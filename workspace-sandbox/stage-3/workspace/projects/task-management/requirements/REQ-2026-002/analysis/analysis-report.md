- **Q-1 / P0 / ask_product / open**：本期‘常用筛选条件’的最小必需集合是什么？
  - 原因：仅登记，本轮未问。条件清单决定核心筛选输入，不能由分析者代选。；影响：无法确定功能范围、测试输入和筛选结果。
  - 关联：FR-1、GAP-1、AC-1
  - 选项：A. 请列出本期必需条件及每项含义；B. 提供已有任务列表筛选规范，并标出本期沿用项；其他；暂不确定
  - 推荐：推荐A，先明确最小可验收集合，避免将‘常用’扩成任意条件。
- **Q-2 / P0 / ask_product / open**：选定条件后，筛选结果应按什么规则匹配？
  - 原因：仅登记，本轮未问。需对已选条件定义匹配，包括空条件、组合条件和无匹配结果。；影响：同样输入可能返回不同任务，核心流程与边界不能验收。
  - 关联：FR-1、FLOW-1、BND-1、GAP-1
  - 选项：A. 多条件均满足才匹配，未选条件不限制原有可见范围，无匹配返回空集；B. 多条件任一满足即匹配，空条件保留原有可见范围，无匹配返回空集；C. 各条件分别规定匹配关系；其他；暂不确定
  - 推荐：以A作为讨论起点，易于预测；需先确认实际条件，不视为已采用规则。
- **Q-3 / P0 / ask_product / open**：在实际常用任务规模下，‘筛选要快’的可接受响应预期是什么？
  - 原因：仅登记，本轮未问。原文明示性能诉求却无核心验收判定；业务等待预期不能被技术机制替代。；影响：无法判定此次速度优化是否达标。
  - 关联：NFR-1、GAP-2、AC-1
  - 选项：A. 由用户给出代表性任务规模及最大可接受等待时间；B. 选择现有代表性慢场景，经演示确认可接受结果并记录测量口径；其他；暂不确定
  - 推荐：推荐B，在没有既定数字时用实际场景形成可验证预期，不编造阈值。
- **Q-4 / P1 / ask_product / open**：筛选失败时是否保留上一次成功结果？
  - 原因：仅登记，本轮未问。失败不能被误认为无匹配结果。；影响：影响错误恢复和结果可信度。
