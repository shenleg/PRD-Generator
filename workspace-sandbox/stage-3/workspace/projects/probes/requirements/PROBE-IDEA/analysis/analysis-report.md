## 5. 待回答问题

下列是登记清单，不表示本轮继续提问；实际提问以 turn-NN.json 为准。

- **Q-1 / P0 / ask_product / open**：这张表主要由谁、在什么工作场景下使用？
  - 原因：尚无核心用户及使用场景，无法确定生成前后的主流程。；影响：可能生成了表，却不符合实际设计或审核任务。
  - 关联：GOAL-1、GAP-1
  - 选项：A. 设计人员编制开关逻辑方案；B. 审核人员校核已有方案；C. 其他，请说明实际用户和场景；D. 暂不确定
  - 推荐：建议先围绕一个真实使用场景说明；若目标是编制方案，可从 A 开始讨论，但目前不视为已选择。
- **Q-2 / P0 / ask_product / open**：你说的“逻辑设计表”具体是哪一种业务结果？
  - 原因：输出对象未定义，这是确定输入和规则之前的前置决策。；影响：无法判断自动生成的结果是否正确。
  - 关联：FR-1、GAP-2
  - 选项：A. 记录开关状态与相应动作关系的表；B. 记录开关间联锁或控制条件的表；C. 其他，可用一个实际表格或小例子说明；D. 暂不确定
  - 推荐：推荐 C，用一个实际结果或小例子确定含义，避免仅凭名称误解；A、B 只是可能解释，不是已确认范围。
- **Q-3 / P1 / ask_product / open**：希望自动生成这张表，主要是为了解决什么问题？
  - 原因：新增功能未提供原因，只需一句定性说明，不索要收益数字。；影响：尚不能判断应优先解决的工作痛点。
  - 关联：GOAL-1
  - 选项：A. 减少人工编制工作；B. 减少漏项或逻辑错误；C. 其他，请简述；D. 暂不确定
  - 推荐：推荐选择最贴近实际的主要痛点并简述，不预设 A 或 B 已成立。
- **Q-4 / P0 / ask_business / open**：明确表的含义后，依据哪些业务输入和生成规则判断正确结果，以及缺失或冲突输入的处理？
