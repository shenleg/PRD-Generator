## 5. 待回答问题

下列是登记清单，不表示本轮继续提问；实际提问以 turn-NN.json 为准。

- **Q-1 / P0 / ask_product / open**：批次已执行一部分后是否允许取消，已成功的申请及尚未执行的申请分别如何处理？
  - 原因：产品尚未决定取消及已成功部分的处理。；影响：决定业务数据是否保留、回退或继续处理，是核心业务决策而非按钮样式。
  - 关联：FR-1
  - 选项：允许取消剩余项，保留已成功项；不允许执行中取消；允许取消并按明确规则处理已成功项；其他或暂不确定
  - 推荐：建议优先评估停止未执行项并保留已成功结果的可理解性和业务适用性，不预设采用。
- **Q-2 / P0 / ask_product / open**：如何判断两次发起属于同一批，以及结果未知或超时后何时可再次发起？
  - 原因：已规定执行中不可重复发起同一批，但批次边界及超时处理未定义。；影响：无法判定重复限制，也可能导致重复执行或任务被误认为结束。
  - 关联：FR-1
  - 选项：按任务标识判定，结果未知时先查询任务状态；按申请集合及业务规则判定；其他或暂不确定
  - 推荐：建议先明确业务上的批次身份与超时后恢复规则，再由研发落实。
- **Q-3 / P1 / ask_design / open**：异步任务的执行、部分失败、超时与取消如何呈现？
  - 原因：仅有常态参考。；影响：影响用户识别任务进度、失败原因及可用操作。
  - 关联：FR-1
  - 选项：补充关键状态低保真和转换说明；先提供状态文案及交互说明；其他或暂不确定
  - 推荐：建议按确认后的业务状态提供最小必要状态稿。
