## 5. 待回答问题

下列是登记清单，不表示本轮继续提问；实际提问以 turn-NN.json 为准。

- **Q-1 / P0 / ask_product / open**：趋势统计的指标是什么，按什么时间维度归属和聚合？
  - 原因：指标口径与时间维度均未定义。；影响：直接决定统计结果，缺失时无法验收。
  - 关联：FR-1
  - 选项：提供明确指标定义及时间归属规则；先限定一个业务指标及时间维度；其他或暂不确定
  - 推荐：建议提供指标、时间归属和聚合规则及示例，由产品确认，不自行指定口径。
- **Q-2 / P0 / ask_product / open**：状态和部门筛选的统计范围与明细范围如何对应？
  - 原因：要求筛选及查看明细，但未定义联动和范围。；影响：影响统计数字与明细是否一致，可能造成错误解读。
  - 关联：FR-1
  - 选项：明细严格对应选中的统计范围与筛选；明细采用不同范围并明确说明；其他或暂不确定
  - 推荐：建议默认考虑统计与明细范围一致，具体规则待产品确认。
- **Q-3 / P0 / ask_product / open**：统计多久更新一次，用户应如何理解数据时间？
  - 原因：刷新规则未定，结果时效影响统计解释。；影响：影响数据正确性预期与验收。
  - 关联：FR-1
  - 选项：按明确周期刷新并展示数据时间；按查询时获取的数据计算；其他或暂不确定
  - 推荐：建议先明确业务可接受的数据时效及展示要求，不预设刷新频率。
- **Q-4 / P0 / ask_product / open**：缺失、重复或异常数据在统计和明细中如何处理？
  - 原因：异常数据处理未定。；影响：影响统计口径及明细对账。
  - 关联：FR-1
  - 选项：排除并明确提示；纳入并标记异常；按异常类型分别处理；其他或暂不确定
  - 推荐：建议按异常类型明确处理及展示，待产品确认。
- **Q-5 / P1 / ask_design / open**：数据展示和明细查看的布局及空、异常状态如何设计？
  - 原因：未提供视觉稿及状态设计。；影响：影响筛选、阅读与明细定位体验。
  - 关联：FR-1
  - 选项：提供低保真布局与关键状态；先提供交互说明；其他或暂不确定
  - 推荐：建议口径明确后依据数据特点选择展示形式。
