## 5. 待回答问题

下列是登记清单，不表示本轮继续提问；实际提问以 turn-NN.json 为准。

- **Q-1 / P0 / ask_product / open**：你希望逻辑设计表的一行主要表达什么？
  - 原因：原文没有说明输出含义，不同表意会导致完全不同的生成规则。；影响：确定表格的核心业务对象及输出语义，而不是先做无关的命名确认。
  - 关联：GAP-1、FR-1、BND-1
  - 选项：A. 一组开关状态及该状态下的逻辑结果；B. 一种操作或触发条件及允许动作、联锁结果；C. 其他：用一个表格行例子说明；D. 暂不确定
  - 推荐：推荐先用 A 的结构提供一个行例子，便于快速说明输入与结果的对应关系；它只是讨论起点，若实际表达条件和动作应选 B，不默认开关二态或必须枚举组合。
- **Q-2 / P0 / ask_business / open**：首版生成完成时，表格应覆盖哪些业务情况才算完整？
  - 原因：输出范围不明可能产生看似完成、实际遗漏的结果；这是生成行为的业务规则，不能只留给技术实现。；影响：明确完整性口径，避免自动生成被默认理解为任意部分、全排列或可静默截断。
  - 关联：GAP-2、FR-1、BND-1、BND-2、Q-7
  - 选项：A. 覆盖约定业务范围内所有符合规则的情况；B. 只覆盖用户明确选定的子范围，并明确标出生成范围；C. 其他：说明完整性的业务口径；D. 暂不确定
  - 推荐：推荐 A 作为完整性讨论起点，避免遗漏被当成完成；约定业务范围及规则仍需确认，A 不等于所有二进制组合。若本来只需子范围，选 B 并明确边界，不由系统自行截断。
- **Q-3 / P0 / ask_product / open**：期望系统主要依据什么业务输入生成这张表？
  - 原因：生成依据未提供，核心输入到输出的流程无法还原。；影响：决定业务输入入口和后续所需资料；现有系统能否提供是另一个研发确认项。
  - 关联：GAP-3、FR-1、Q-9
  - 选项：A. 用户给定的开关信息和逻辑规则；B. 用户提供的设计资料或既有表格；C. 系统内已有的项目、设备或关系数据；D. 其他：说明主要输入，可补充必要组合；E. 暂不确定
  - 推荐：推荐先按 A 描述一个小输入例子，因为无需假定已有数据或导入能力就能讲清生成依据；不是决定新增配置页面。实际依赖资料或现有数据则分别选 B 或 C，是否具备对应能力由研发核查。
- **Q-4 / P0 / ask_product / open**：首版优先用于哪一个工作场景？
  - 原因：核心使用者及使用环节没有提供。；影响：确定核心用户和使用场景，后续复核是否涉及交互界面。
  - 关联：GAP-4、GOAL-1
  - 选项：A. 设计人员编制或核对逻辑方案；B. 仿真或测试人员验证逻辑；C. 运行人员查询操作条件；D. 其他：说明一个优先场景；E. 暂不确定
  - 推荐：推荐 A 作为讨论起点，因为原文称逻辑设计表；不是已确认使用者身份，若用于验证或查询应选 B 或 C。
- **Q-5 / P0 / ask_business / open**：用什么业务依据判定每行逻辑结果正确？
  - 原因：生成规则及正确性标准均未给出，核心规则与验收不能落定。；影响：明确合法与不适用情况、输入对应的正确结果，并据此形成可验证案例；不能补造联锁或计算规则。
  - 关联：GAP-5、BND-1、FR-1、Q-1、Q-2、Q-3
  - 选项：A. 依据业务已确认的规则或标准，并用样例核对；B. 本次由业务明确判定规则，再共同形成对照样例；C. 其他：说明权威判定依据；D. 暂不确定
  - 推荐：已有明确规则时推荐 A，便于追溯和验收；没有则选 B，不能假装已有标准或正确样表存在。
- **Q-6 / P0 / ask_product / open**：必需输入缺失或规则冲突导致结果不可判定时，应采取哪种输出策略？
  - 原因：异常下的预期行为未知，不能把不确定结果默认为正确输出。；影响：给 EXC-1 明确业务处理，后续可验证异常输出。
  - 关联：GAP-6、EXC-1、Q-3、Q-5
  - 选项：A. 停止正式生成并明确原因；B. 输出可判定部分，同时明确标记不完整及原因；C. 其他：说明处理策略；D. 暂不确定
  - 推荐：推荐 A，防止依据不足的表被当成完整设计结果；若确需部分结果则选 B，再明确可判定边界。
- **Q-7 / P1 / ask_product / open**：若确认存在随规模增长的组合结果，较大结果集应怎样供业务使用？
  - 原因：这是组合语义尚未确定时的条件性规模边界，不假定已经遇到性能问题。；影响：决定能否分批使用或先明确子范围，保护 Q-2 所定完整性口径；当前不设任意上限或截断。
  - 关联：GAP-7、BND-2、Q-1、Q-2、Q-9
  - 选项：A. 保留约定范围的完整结果，分批查看或选择；B. 由用户明确缩小业务范围后重新生成，并标注该范围；C. 其他：说明大结果集使用方式；D. 暂不确定
  - 推荐：在必须保留全范围时推荐 A，以避免静默丢失；若业务允许缩小范围选 B，不能由技术自动选取一部分。机制是否支持另由研发核查。
- **Q-8 / P1 / ask_product / open**：自动生成主要希望解决什么现有问题？
  - 原因：原文没有给出新增功能原因，仅需一句主要痛点。；影响：支持必要性与价值判断，不索要频率、成本或收益数字。
  - 关联：GAP-8、GOAL-1
  - 选项：A. 减少手工编表；B. 减少逻辑遗漏或核对错误；C. 其他：说明主要问题；D. 暂不确定
  - 推荐：推荐从 A 核对，因为自动生成直接对应手工编制的替代；若主要关注正确性应选 B，两项均未被确认。
