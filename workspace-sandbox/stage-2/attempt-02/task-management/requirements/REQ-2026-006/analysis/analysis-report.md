## 5. 待回答问题

下列是登记清单，不表示本轮继续提问；实际提问以 turn-NN.json 为准。

- **Q-1 / P0 / ask_product / open**：哪些结束状态触发通知？
  - 原因：跑完没有精确定义。；影响：核心触发不可验收。
  - 关联：FR-1、GAP-1、REQ-2026-004/STATE-1
  - 选项：仅成功完成；成功或失败结束；成功、失败与取消或终止都通知；其他；暂不确定
  - 推荐：推荐成功或失败结束都通知，便于了解执行结果；取消是否通知不自动决定。
- **Q-2 / P0 / ask_product / open**：通知接收者是谁？
  - 原因：用户指代不清。；影响：可能漏发或发错对象。
  - 关联：FR-1、GAP-1、AC-1
  - 选项：发起本次任务的人；工程创建者；明确订阅该任务的人；其他；暂不确定
  - 推荐：推荐任务发起人，与本次执行关系最直接；尚未确认。
- **Q-3 / P0 / ask_product / open**：本期使用什么通知渠道？
  - 原因：渠道未指明。；影响：核心输出和验收不完整。
  - 关联：FR-1、GAP-1、AC-1
  - 选项：站内通知；邮件；站内和邮件都发；其他；暂不确定
  - 推荐：推荐先讨论站内通知，保持在任务使用场景中；不是现有能力结论。
- **Q-4 / P0 / ask_product / open**：同一次执行的同一结束结果重复到达时通知几次？
  - 原因：重复事件可能重复打扰。；影响：关键重复边界预期未定。
  - 关联：BND-1、GAP-2
  - 选项：同一结束结果只通知一次；每次收到结束事件都通知；其他；暂不确定
  - 推荐：推荐同一结果一次，减少重复打扰；新执行或重试产生的新结果不自动归为同一次。
- **Q-6 / P1 / ask_product / open**：新增通知主要解决什么困难？
  - 原因：原因未明确，只轻量确认一句。；影响：影响必要性和范围取舍。
  - 关联：GOAL-1、GAP-2
  - 选项：减少等待时反复查看列表；协作用户及时获知执行结果；其他；暂不确定
  - 推荐：推荐先按减少反复查看讨论，与任务场景贴近；只是推断，不要求收益数字。
- **Q-7 / P1 / ask_product / open**：通知发送失败后应该怎样处理？
  - 原因：失败后的业务要求未定。；影响：影响补发与用户感知。

  - 推荐：推荐记录并重试，减少暂时故障漏通知；不预设次数或实现能力。
