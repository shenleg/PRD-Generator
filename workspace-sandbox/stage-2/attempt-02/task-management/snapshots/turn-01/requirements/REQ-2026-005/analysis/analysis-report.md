## 5. 待回答问题

下列是登记清单，不表示本轮继续提问；实际提问以 turn-NN.json 为准。

- **Q-1 / P0 / ask_product / open**：超过1000条时，最终应导出多少数据？
  - 原因：上限与全部结果不丢失的说法冲突。；影响：可能截断或漏数据，核心输出无法验收。
  - 关联：BR-1、BR-2、CNF-1、GAP-1、BND-1
  - 选项：总量最多1000条，超限时明确提示；完整导出所有结果，1000不作为总量上限；每份最多1000条，分多份覆盖全部结果；其他（请说明规则）；暂不确定
  - 推荐：推荐每份最多1000条、分多份覆盖全部结果，作为兼顾两句原文的讨论方案；分多份是新增候选，不是原文事实，也没有确认技术可行。
- **Q-2 / P0 / ask_product / open**：本期导出哪些字段？
  - 原因：常用字段没有清单。；影响：无法判定核心输出内容。
  - 关联：FR-1、GAP-2、AC-1
  - 选项：直接列必需字段及业务含义；以旧报告字段为起点确认本期清单；其他；暂不确定
  - 推荐：推荐对照旧报告确认本期字段，符合格式延续诉求；不在拿到报告前补造字段。
- **Q-3 / P0 / lookup / open**：需要补充之前的报告样例或明确格式说明。
  - 原因：所指资料未提供，不做历史检索。；影响：文件类型、列顺序及值格式不可核对。
  - 关联：BR-3、GAP-2、AC-1
  - 选项：无交互选项
  - 推荐：未填写推荐
- **Q-4 / P0 / ask_product / open**：一次导出的结果集合按什么范围确定？
  - 原因：全部结果及一条记录的粒度未知。；影响：可能导错范围或错误计数。
  - 关联：GAP-2、BND-1、AC-1
  - 选项：单个任务的结果记录，并明确记录粒度；用户选中任务的结果集合，并明确记录粒度；当前筛选范围的结果集合，并明确记录粒度；其他；暂不确定
  - 推荐：推荐先明确单任务结果集合，便于定义全部及计数；只是讨论起点，未排除其他范围。
- **Q-5 / P0 / ask_product / open**：导出只有部分数据生成成功时如何认定本次结果？
  - 原因：不要丢数据必须有部分失败预期。；影响：不完整输出可能被当成完整报告。
  - 关联：EXC-1、GAP-3
  - 选项：本次失败，不作为完整导出交付；明确标为部分结果及缺失范围，允许补齐；其他；暂不确定
  - 推荐：推荐本次失败并明确提示，避免用户误用不完整结果；尚未采用。
