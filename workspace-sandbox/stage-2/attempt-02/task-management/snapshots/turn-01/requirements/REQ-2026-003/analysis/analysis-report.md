## 5. 待回答问题

下列是登记清单，不表示本轮继续提问；实际提问以 turn-NN.json 为准。

- **Q-1 / P0 / ask_product / open**：本次批量删除最终允许哪些用户操作？
  - 原因：两处删除授权说法可能冲突，需先明确本次操作权限。；影响：可能造成非授权删除，权限矩阵不能验收。
  - 关联：BR-1、BR-2、CNF-1、GAP-1
  - 选项：仅工程创建者和管理员；所有用户；其他（请说明角色及范围）；暂不确定
  - 推荐：推荐仅工程创建者和管理员，依据第5条明确限制，避免把不清楚的授权直接放宽；作业与任务关系仍保留待定，推荐不等于已确认。
- **Q-2 / P0 / ask_product / open**：本次批量删除的实际业务处理规则是什么，原文的之前逻辑具体指什么？
  - 原因：旧处理规则未提供，不能仅按文字猜测数据去留。；影响：无法判定删除后的对象、关联结果及恢复后果，存在数据丢失风险。
  - 关联：BR-3、GAP-2、AC-1
  - 选项：沿用旧规则：请提供规则资料，或描述删除后对象与关联结果如何处理及能否恢复；本次重新定义删除后果：请明确对象记录和关联结果各自保留还是删除、是否允许恢复；其他（请说明实际规则）；暂不确定
  - 推荐：推荐沿用并补齐旧规则，原文明确要求按之前逻辑，先取得其实际内容可避免擅自改变数据后果；不能只凭选择沿用就当作已取得规则。
- **Q-3 / P0 / ask_product / open**：作业与任务是什么关系？
  - 原因：术语混用会影响最终对象范围，但不阻止先针对批量删除确认操作规则。；影响：后续可能需拆分对象及权限矩阵，不能直接合并。
  - 关联：FR-1、FR-2、GAP-3
  - 选项：同一业务对象的两种称谓；不同对象，分别定义；上下级对象（请说明关系）；其他；暂不确定
  - 推荐：推荐先核对同义这一可能，整体主题相同；没有回答前不采用，也不让它挤掉本轮数据后果决策。
- **Q-4 / P0 / lookup / open**：缺少原文所指的旧删除逻辑文档或业务说明，需要补充；不执行历史检索。
  - 原因：旧逻辑未作为附件提供。；影响：如不能用明确业务回答替代资料，核心删除后果仍不可判定。

  - 选项：无交互选项
  - 推荐：未填写推荐
- **Q-5 / P0 / ask_product / open**：运行中的对象允许怎样删除？
  - 原因：执行中删除可能改变运行或结果。；影响：关键状态边界无法验收。
  - 关联：BND-1、GAP-4、CON-1

- **Q-6 / P0 / ask_product / open**：批量中部分对象不能删除时怎样处理整批结果？
  - 原因：混合权限、状态或失败可改变数据结果。；影响：不能判定应保留和删除哪些对象。
  - 关联：BND-1、EXC-1、GAP-4
  - 选项：逐项处理并明确成功失败；任一项不满足条件则整批不删除；其他；暂不确定
