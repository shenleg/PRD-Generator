## 5. 待回答问题

下列是登记清单，不表示本轮继续提问；实际提问以 turn-NN.json 为准。

- **Q-1 / P0 / ask_product / open**：请用哪种资料说明一个真实状态错误样例？
  - 原因：有时候显示不对不足以复现缺陷。；影响：不能确定修复目标与回归范围。
  - 关联：FR-1、GAP-1、AC-1
  - 选项：给操作步骤、实际状态及期望状态；给带任务场景说明的截图或记录，并指出正确状态；其他；暂不确定
  - 推荐：推荐先给一例步骤及实际、期望状态，最直接形成可复现验收；不假设某种错误已经发生。
- **Q-2 / P0 / ask_product / open**：正确状态按哪份业务定义判断？
  - 原因：没有合法状态与转换说明。；影响：核心输出不确定。
  - 关联：STATE-1、GAP-1、AC-1
  - 选项：沿用现有状态含义，提供状态定义；本次重新确认状态及合法转换；其他；暂不确定
  - 推荐：推荐先提供现有定义，避免修复时意外改变业务语义；资料未取得前仍待定。
- **Q-3 / P0 / ask_product / open**：业务能接受的状态显示延迟如何定义？
  - 原因：实时缺少可测标准，更新技术不是业务容忍值。；影响：不能判断实时要求是否交付。
  - 关联：NFR-1、BND-1、GAP-1
  - 选项：从任务状态实际变化到页面可见，给最大延迟；按指定业务操作后看到正确状态的时间窗，给容忍值；其他；暂不确定
  - 推荐：推荐实际变化到页面可见的延迟，直接反映实时体验；数值由用户确定，不编造。
- **Q-5 / P0 / ask_product / open**：获取不到新状态时，应显示什么业务结果？
  - 原因：异常显示可能误导任务是否结束。；影响：关键异常路径无法验收。
  - 关联：EXC-1、GAP-2
  - 选项：保留上次状态并明显标记未更新；显示状态未知或获取失败；其他；暂不确定
  - 推荐：推荐保留上次状态但标记未更新，保留上下文又不冒充实时结果；未采用。
