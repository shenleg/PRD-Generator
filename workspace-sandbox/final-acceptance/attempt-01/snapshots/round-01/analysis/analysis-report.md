## 5. 待回答问题

下列是登记清单，不表示本轮继续提问；实际提问以 turn-NN.json 为准。

- **Q-1 / P0 / ask_product / open**：最终允许撤回哪些状态的申请？
  - 原因：原文第2条的全部已提交、仅待审批及通过未下单三种口径互相矛盾。；影响：无法判定合法撤回状态。
  - 关联：BR-1、BR-2、BR-3
  - 选项：仅待审批；待审批和审批通过但未下单；其他；暂不确定
  - 推荐：建议待审批及通过未下单均可，能满足更正诉求，但必须由业务确认。
- **Q-2 / P0 / ask_product / open**：本期谁能撤回哪些人的申请？
  - 原因：第3条明确未定创建人与管理员的权限。；影响：可能引入越权批量操作。
  - 关联：BR-4
  - 选项：仅创建人撤自己的；创建人加采购管理员代撤；其他；暂不确定
  - 推荐：建议仅创建人，先保持最小权限边界。
- **Q-3 / P0 / ask_product / open**：撤回与审批或下单同时发生时，以什么业务结果判定成功或失败？
  - 原因：原文禁止已购买后又撤回，但未规定按执行时还是页面快照判断及先后结果。；影响：可能出现撤回与下单均成功的矛盾。
  - 关联：BND-1、FR-1
  - 选项：执行时最新状态与权限逐条判定，先成功者生效；以页面打开时状态为准；其他；暂不确定
  - 推荐：建议以执行时最新状态判定，并明确先后动作的业务结果；实现方式交研发。
- **Q-4 / P0 / ask_product / open**：撤回成功后原申请变为什么状态，重新提交是否沿用申请编号？
  - 原因：可修改后重提没有定义状态和身份。；影响：核心状态流程不能还原。
  - 关联：FLOW-1、BR-5
  - 选项：原申请回草稿并沿用编号；产生新的申请；其他；暂不确定
  - 推荐：建议回草稿保留原申请编号，避免历史断链。
- **Q-5 / P0 / ask_product / open**：同批部分失败时，已成功项是否保留，结果逐条需要显示什么？
  - 原因：不应卡住其他申请不等于已明确回滚和最终反馈。；影响：无法验收混选批次。
  - 关联：BR-6、BND-2
  - 选项：逐条处理，保留成功并给失败原因；任一失败则整批不变；其他；暂不确定
  - 推荐：建议逐条处理，与原文部分失败不阻塞意图一致。
- **Q-6 / P0 / ask_product / open**：一次提交对应哪些已选申请，空选择、最大数量及超限时如何处理？
  - 原因：未说明仅勾选、跨页或筛选全量；数量边界没有依据。；影响：输入范围和边界验收不明确。
  - 关联：BND-3
  - 选项：只处理当前明确勾选的申请，明确单批边界；处理筛选结果全量；其他；暂不确定
  - 推荐：建议仅明确勾选范围；上限须业务结合实际列表确认，不能凭空给数。
- **Q-7 / P0 / ask_product / open**：重复点击或重试遇到已撤回申请时，业务结果和成功日志如何处理？
  - 原因：重复撤回可能改变结果或重复留痕。；影响：同一撤回的业务含义及重试验收不明确。
  - 关联：EXC-1
  - 选项：返回已撤回，不再次撤回或重复成功留痕；按新撤回再次处理；其他；暂不确定
  - 推荐：建议已撤回不再执行，用可识别结果防重复。
- **Q-8 / P0 / ask_product / open**：撤回后旧审批待办如何失效，重提是否启动新审批轮次？
  - 原因：历史保留不等于待办失效和重提流程明确。；影响：旧审批可能继续生效或错误沿用上次结果。
  - 关联：BR-5、FLOW-1
  - 选项：旧待办失效，重提开启新审批轮次；沿用原审批待办与通过结果；其他；暂不确定
  - 推荐：建议保留历史但开启新轮次，避免旧决定套用修改后的申请。
- **Q-9 / P1 / ask_product / open**：沿用日志时至少需要哪些可查询信息，本期是否需要新增查询页面？
  - 原因：已有日志字段未提供，产品的最小追溯预期仍需说明。；影响：影响操作追溯及范围。
  - 关联：CON-1
  - 选项：记录逐条操作与结果，沿用查询页面；只记录批次数量汇总；其他；暂不确定
  - 推荐：建议保留逐条结果以便追溯失败。
