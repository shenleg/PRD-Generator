# PRD 生成与增量同步

本 Skill 支持首稿、同分析输入重复生成及未发布工作稿的增量同步。编辑、提交评审、发布及发布后另建工作稿尚未实现；收到此类请求说明边界，不模拟完成。需求内容修改或含义不明的改动交回 Requirement Analyst，由用户决定后续分析；不调用分析写入器。

## 流程

1. 确定已有需求目录和可选项目模板。没有需求目录或分析结果时建议先做需求分析，不创建需求。仅以 `analysis/analysis-result.json` 为业务权威；不读人用分析报告，不写 `analysis/`。跨需求分析只接受用户显式提供的路径。
2. 读取 [门禁和降级](references/gating-rules.md)。首稿运行 `check_gate.py`；每次操作已有 PRD 前读取 [同步规则](references/sync-rules.md)，运行只读 `check_sync.py` 检查门禁及待同步状态。展示全部诊断，失败即停止；过期时先建议重评，用户明确坚持后才允许过期草稿。检查或查看请求本身不授权写入。
3. **需要同步时**，按同步规则以旧稿为基础，只改受影响内容，未变条目保留原始字节和编号。核实每个缺口的唯一接收问题与实际内容，充分才关闭，交接或问题状态变化不等于补足。用 `write_draft.py --sync` 统一保存；不要用首稿整篇重写或独立编号写入绕过同步。成功后直接进入第 6 步。
4. **首稿或同输入重复生成时**，读取 [内容生成](references/generation-rules.md)、[章节结构](references/prd-structure.md) 和 [编号追溯](references/numbering-and-trace.md)。按有效分析构造正文、遗留事项及确有必要的缺口，不以空必有章节自动认定缺口；模板必需而分析缺失的信息占位登记。构造独立映射补丁，调用 `assign_ids.py` 取得脚本分配的候选编号；不自行编号，默认不写入。
5. 按 `templates/prd.md` 构造带定位标记的候选，由 `write_draft.py` 统一保存并渲染文档信息。命令：`write_draft.py REQUIREMENT_DIR --patch PATCH.json --body CANDIDATE.md --candidate-dir NEW_DIRECTORY`；可选 `--gaps GAP_REQUESTS.json`。候选目录须在正式需求及关联分析目录外且不存在，不用编号 `--write` 代替统一保存。
6. 保存前核对候选、读时版本、分析及待写文件；并发变化则重读，不覆盖。展示全部警告；失败保留候选及诊断，不宣布完成。连续三次修正仍失败即停止。中断按入口返回信息显式 `--recover`，不重复追加事件。
7. 成功后说明草稿类型、实际变化、缺口关闭依据或保留原因、遗留事项及文件位置，不暗示已评审或发布。只读查看不能宣称已同步。

编号、摘要及格式以相应脚本和生成规格为准；机器校验不代替语义忠实性、缺口充分性及未标记文本的人工审查。变更摘要使用 [模板](templates/change-summary.md)，只记录实际变化。
