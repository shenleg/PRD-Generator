# 增量同步与缺口核实

本文规定已有 PRD 的定向同步。已发布需求按[版本规则](versioning-and-release.md)另建或递增工作稿，快照保持不变；已废弃需求停止同步。生成侧只读分析，不调用分析写入器。

## 1. 检查与定位

每次操作已有 PRD 前运行 `check_sync.py REQUIREMENT_DIR`。它复用分析门禁，只读返回修订基准、`pending`、既有正式条目的 `items` 差异、未映射的本需求新增来源 `added`，以及有依据时的 `sections` 比较；缺旧章节依据的分类为 `unknown`，不伪装成未变。不写文件。显式跨需求资料使用 `--related-analysis PATH`，只参与所引条目的比较，不把另一需求的全部功能导入本稿。

- `pending` 由当前分析修订是否高于 `prd.based_on_analysis_revision` 得出，不另存状态。
- `items[].category` 为 `unchanged`、`modified`、`withdrawn`、`to_reassess`；按完整来源摘要判定。正文未变而标签、来源、关联或其他生成字段变化也属于变化。
- 对象键顺序和 JSON 排版不造成来源变化；数组顺序保留。来源摘要不等于 Markdown 原始字节摘要。
- 修订变化不等于所有条目变化；只有修订增加时，更新信息、汇总和事件，未变正式条目仍保留原文。
- 缺引用、未来基准或门禁失败则停止；不要把无法找到来源当作撤销。旧稿仍带旧标签或撤销前状态是同步的输入，不用“旧稿已符合新分析”作同步前提。

展示全部诊断。过期分析先建议重新评估；只有用户明确坚持才加 `--allow-stale`，结果只能为 `stale_draft`。分析事件不可用时不猜原因；来源清单不可用时显示 `source_id`，不能绕过仍可执行的上游校验。

## 2. 定向构造候选

以当前工作稿为基础，不从空白整篇重写。

1. 用差异定位需改写的条目及相关标注、来源、关联表达；一对多或多来源映射逐项核对。
2. 未变正式条目连同定位标记保持原始字节、原章节、编号及引入版本。不要顺带润色或重排。
3. 已撤销来源对应条目退出有效章节，既有追溯保留为 `abolished`，变更记录留痕；不删除身份、不复用编号，也不自动废弃整个需求。
4. 待重评条目改为 `to_confirm` 并保留【待确认】及其他适用标注。新增使用独立映射补丁，由脚本分配新号；先用 `assign_ids.py` 的只读候选取得新号，不用独立 `--write` 拆开保存。
5. 按当前权威分析核对非编号内容，重新汇总遗留事项、草稿类型和提示。缺省辅助资料的未覆盖能力由保存入口登记到信息中，不臆造结论。

新生成的追溯还记录可选的 `meta.section_source_digests`：章节所用完整分析集合、占位及关闭依据的稳定摘要。依据未变的整章（含定位标记）保持原始字节，避免只改功能时顺带改范围等非编号文字；`info`、`changes` 由脚本渲染，仍按版本变化。编号条目继续独立保护，不能因整章受影响而润色其中未变条目。

旧追溯无章节摘要仍可读；可用 `write_draft.py --sync --previous-analysis OLD_ANALYSIS.json ...` 显式提供身份及修订匹配原基准的旧分析，不能用当前分析伪装旧依据。既无旧摘要又无可信旧分析时，脚本明确警告“旧稿章节依据不足”，保留正式条目保护并在成功后建立新摘要；此时须补旧分析或人工逐章核对，不宣称整章最小化已被自动证明。相关分析旧快照不齐的章节同样降级。

拆分术语前的工作稿和发布快照沿用旧附录映射，只读检查不改写，同输入重复生成也保留旧正文。首稿和后续增量同步采用[新版章节映射](prd-structure.md)：把已有术语移到 `glossary`，从附录移除重复术语；旧稿没有独立术语依据时核对实际内容，不把术语判为未变。新版中只修改术语不开放附录改写。

同步编号补丁仍使用 `patch_version: "1.0"` 及读时版本/修订；无需逐项重列未改映射，统一写入器会重算全部既有依据。旧无键身份需明确定位时用已有 `prd_id`。新分析条目不能静默漏映射。不能向补丁提交正文、缺口、摘要或计数器。

## 3. 缺口核实

逐项读 `gap-requests.json` 的原描述，使用本需求问题的 `gap_request_ref` 唯一对应。关闭须同时满足：

1. 唯一接收问题不再 `open`。
2. 当前分析确有足够的有效内容，或明确记录了原内容不再需要的依据。

`handed_over` 只表示成功接收；问题有答案或状态已变也不能单独证明补足。实际内容不够、仍待重评、已撤销或无法唯一对应时，保留原请求及占位，向用户说明缺少的内容并建议返回分析。若上游拒绝重复接收等坏输入，如实报告，不自行修分析。

确认足够后，在完整缺口候选中仅把对应状态改为 `closed` 并填写既有 `resolution`：

- `kind: supplied`：引用实际补足所需内容的有效分析条目。
- `kind: not_needed`：引用明确说明不再需要的分析决策或范围依据，不能只写生成器自己的理由。
- `analysis_refs` 为非空完整引用，`reason` 具体说明这些依据如何覆盖原缺口。

移除或以有依据的内容替换唯一占位；保留缺口身份、描述、登记版本、历史计数器和扩展字段，其他未关闭缺口及占位保持。暂定假设可以补足，但正文仍带【暂定】，假设依据、验证方式和遗留事项继续存在，不能升级为已确认事实。

脚本核对结构、引用、有效状态、唯一接收和占位关系，不认证自然语言充分性。对照原缺口逐项评审，不能以“校验pass”代替内容核实。

## 4. 统一保存与反馈

命令：

```text
write_draft.py REQUIREMENT_DIR --sync --patch PATCH.json --body CANDIDATE.md --candidate-dir NEW_DIRECTORY
```

按需增加 `--gaps GAP_REQUESTS.json`、显式 `--related-analysis PATH` 或用户实际坚持后的 `--allow-stale`。候选是含稳定定位块的完整 Markdown，但只定向修改；保存入口渲染文档信息和变更记录。候选目录须为正式需求及关联分析目录之外的新目录。

统一入口重新检查门禁、版本及当前全部输入，核对未变正式条目原字节，校验完整候选，再保存正文、追溯、缺口、追加事件及 `prd` 块。同步产生新版本并回到 `draft`：首发前使 `0.N` 递增；首发后按[版本规则](versioning-and-release.md#工作稿版本与基线)构造 `-draft` 号，继续使用旧已发布基线，直到新稿正式定稿。原 `common` 及其他块不变。旧缺口不能由生成器改为 `handed_over`，该状态仍只由分析侧维护。

脚本将同步事件渲染为 [两列变更概览和分版本明细](../templates/change-summary.md)。可读分析事件仅补充相应修订区间的原因，权威事实仍来自分析结果；展示不改写事件日志。

- 并发冲突：重读并重新定位，不仅修改补丁数字重试。
- 校验失败：保留候选和具体诊断，不宣布成功；连续修正三次仍失败即停止。
- 写中断：报告实际已写范围及未完成事务，显式使用 `write_draft.py REQUIREMENT_DIR --recover` 恢复；不重复同步或假称原子完成。
- 成功：展示草稿类型、实际变更、保留及关闭缺口的依据、仍有的遗留事项和所有警告。生成或同步成功不表示获准评审或发布。
