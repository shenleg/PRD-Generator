## 分步实施

1. **显式对照（首个增量）**：在用户确认历史资料及测试边界后，为同需求基线/提议结果实现只读compare_baseline.py。复用唯一validator；按已有稳定编号比较added/modified/missing/unchanged，保留来源与修订；条目依赖方向计算显式直接/间接影响；missing是差异，不代表已授权删除。无资料返回降级，不自动搜全工作区。
2. **历史语义对照**：对用户指定的不同需求资料识别重复、冲突、依赖，由分析侧产出CNF/Q和变更建议补丁，通过更新器保存。语义判断不塞进机械脚本；基线原字节不变。先验证RA-14/15/16。
3. **资料索引与有限检索**：定义project-index/source-index；实现index_sources.py、search_project.py，关键词/需求号/模块/标签/术语过滤、限定结果条数和摘录，记录来源定位，不引入向量数据库/RAG服务。支持刷新，不随意删除用户资料。
4. **过期与联动**：保存检索采用的资料版本、指纹及更新时间；资料/基线变化时经补丁标stale并重评受影响项。时间阈值显式配置，未知更新时间不编造。验证RA-17/18/19。
5. **接入Skill与最终回归**：写historical-retrieval.md、渐进引用和场景剧本。新增字段先核对兼容约定；历史证据绑定阶段4提交或既有源码快照，新行为单独测试，不重写旧哈希。

## 首个增量拟测试的公共接口（待用户确认）

优先使用与现有脚本一致的 **CLI边界**：

`python -I -B skill/requirement-analyst/scripts/compare_baseline.py --baseline BASELINE_RESULT --proposal PROPOSAL_RESULT`

输入为显式文件路径，来源清单默认邻接；跨需求引用需显式传资料。输出单一JSON，退出码pass=0/warning=1/fail=2，文件只读。先从合法同需求结果的条目差异/基线不变这一条垂直切片测试，再迭代校验失败、缺资料及影响传播；不先批量写想象中的全部测试。

替代边界为Python公共API加CLI。若用户选择该边界，先明确API返回值和异常规则再写测试。不测试私有辅助函数，不提前固定未约定实现。

## 用户已确认与首个增量（2026-11-16）

用户在明确的选择题中选择 **“合成历史资料 (Recommended)”** 与 **“CLI 集成测试 (Recommended)”**。据此允许构造测试用途历史基线，不把它当真实系统已发布规则；测试边界确定为公开CLI。

已完成 `scripts/compare_baseline.py` 首个切片和6项CLI集成测试：

- 显式传同需求的基线/提议分析路径，分别调用唯一校验器；来源清单默认邻接，关联结果显式提供。
- 按稳定编号及完整条目值、集合位置区分added/modified/missing/unchanged，输出before/after、需求限定引用及两个分析修订号；撤销和待重评保留为状态变化而非物理删除。
- 两个输入及其来源全程只读，不调整任何baseline_revision。资料是否已发布须另有依据，missing不是删除授权。
- 无指定基线时先校验提议结果，再warning降级；不自动搜索，不声称无冲突。fail优先于stale，合法stale保留warning。坏JSON、重复键、NaN、身份不符及未知参数返回结构化fail。
- 未增加语义模型、索引、搜索或自动写分析功能。

首个测试在脚本不存在时实际失败，完成最小实现后通过；后续测试复现“无历史降级绕过提议校验”，再修正为先校验，新增6项现全部通过。

调用例：

```bash
uv run --offline --no-project --python /usr/bin/python3 --with-requirements tests/requirements.txt \
  python -I -B skill/requirement-analyst/scripts/compare_baseline.py \
  --baseline /path/to/baseline/analysis-result.json \
  --proposal /path/to/proposal/analysis-result.json
```
