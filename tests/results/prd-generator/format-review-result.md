## 独立只读审查与实际复现

独立读取生产文件和认可协议后提出四项具体问题。该审查未能用其直接 Python 环境执行探针，因为环境缺少 `jsonschema`；不能声称独立动态验证已通过。主会话随后在项目既有 `uv` 环境增加真实回归，四项均复现为失败，再修复。

| 问题 | 实际修正 | 回归测试 |
| --- | --- | --- |
| 隐藏标记代替可见正式编号 | 去掉注释后，在条目可见内容中检查编号；同样保护标注和来源显示 | `test_review_hidden_id_does_not_replace_visible_id`、`test_hidden_label_cannot_replace_visible_annotation` |
| 旧条目无稳定键时补丁能改变类别 | 按旧正式编号定位后仍检查原类别，不只检查映射键命中 | `test_review_legacy_mapping_cannot_change_kind` |
| 不同补零形式重复使用同一数值序号 | 同时核对编号字符串及类别数值序号唯一性 | `test_review_numeric_sequence_cannot_be_reused_with_zero_padding` |
| 待同步警告未列变化引用 | 比较完整生成摘要，逐条给出受影响引用，保持 warning 不误报结构失败 | `test_review_sync_warning_lists_changed_references` |

- 评审回归红灯：`stage-1-review-red-test-run.txt`，实际运行 `37` 项，四项失败。
- 修正后首轮新测试绿灯：`stage-1-review-green-test-run.txt`，`42` 项通过。
- 随后补充隐藏标签、空 JSON、非法状态类型及保存证据重放检查；最终全量 `263` 项通过，详见 `stage-1-final-test-run.txt`。
- 最初实现缺失红灯、首轮全量通过和全部历史日志均保留，没有改写旧失败。
