# 阶段 4：非编号章节最小同步保护补充草案

本文说明独立复核发现的协议缺项。**用户已于 2026-11-17 真实选择“增加章节摘要（推荐）”，见 `stage-4-section-approval.json`；评审时原字节保存在 `stage-4-section-reviewed.md`。获确认部分已先回写规格再实现。**

## 已复现的问题

仅查询功能的分析发生变化时，候选同时把“本期不含支付功能”改成“本期包含支付功能”，现有脚本仍能保存且格式校验通过。当前 `source_digest` 只记录正式条目的生成依据，不能判断范围、背景、术语等非编号正文是否受影响。问题不在自然语言是否能自动理解，而在缺少旧依据，无法执行确定性的未变章节保护。

已有执行计划要求“先补协议再实现”。不通过字符串包含、猜测分析变化或把新摘要当旧摘要解决。

## 建议：追溯中增加可选章节依据摘要

1. 在 `prd-trace.json` 的 `meta` 增加可选 `section_source_digests`，以稳定章节键映射到 `sha256:` 摘要。它记录生成时该章节所用完整分析数据及适用辅助来源名称的稳定摘要，不保存正文或当前分析状态的第二份权威值。
2. 首稿及每次成功同步由脚本计算；字段与正式条目摘要分开。对象键排序、紧凑 UTF-8、保留数组顺序、拒绝非有限值的规范保持一致。
3. 章节依据不变时，整章原始字节保持；正式条目继续执行原有独立字节和身份保护。依据变化时只改对应章节，未变正式条目仍不改。`info` 与 `changes` 由脚本更新，不参加这项比较。
4. 摘要覆盖固定章节映射的完整来源集合：范围和目标；场景；功能；业务规则；流程状态；边界异常；约束；验收；价值；界面；技术及研发问题；影响；遗留问题/假设/决策/矛盾/缺口及推断内容；附录术语和实际来源。缺口候选状态及关闭依据纳入其占位所在章节的依据，避免合法关闭被误拦截。生成器不因非业务 JSON 排版变化重写章节。
5. 旧 `1.0` 追溯缺少此字段仍可读取，不能据此重编号。同步时可显式提供与旧基准修订匹配的 `--previous-analysis PATH` 作为首次建立章节比较的旧权威快照；不把当前分析重新哈希后冒充旧依据。
6. 旧稿没有章节摘要且没有可验证旧分析时：未变正式条目的保护继续执行；对无法确定依据是否改变的非编号章节明确提示证据不足，要求先提供旧分析或人工逐章核对，本轮不能宣称已自动证明全篇最小同步。该限制不因辅助分析事件或来源清单缺失而冒充权威分析失败。
7. Schema 仅增加兼容的选填字段，校验字段结构和当前同步稿的摘要一致性；实际自然语言忠实性和缺口充分性仍由人工评审。

拟回写生成规格 §6.2、§9.4、§9.9、§9.10 及脚本说明，不改变编号补丁、缺口或事件的现有业务协议。修改后重跑程序回归，已冻结模型结果保留原样，使用当前源码另行重放真实候选并明确非新模型调用。
