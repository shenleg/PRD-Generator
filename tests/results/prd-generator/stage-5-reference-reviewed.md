# 阶段 5：修改分流与手工修改检测参考草案

本文用于人工确认预期分流及处理结果，不是运行记录，不作为被测模型输入。**状态：待用户认可。**本次参考认可不等于实际输出评审、阶段验收或发布确认；阶段 0～4 已封存材料及认可范围保持不变。

## 输入与评审范围

- 使用隔离的合成需求和已有未发布工作稿，分析保持不变。分别验证用户提出修改与用户已经手工改稿两种情况，不把“修改请求”自动视为已改稿。
- 基础规则示例为“用户可以导出当前筛选结果”；另准备其他未变条目、范围章节和已有遗留事项，防止仅验证一个条目而漏掉正文其他位置。
- 修改前后保存正文原始字节、追溯、缺口、元数据、事件、分析目录指纹及实际对话。正式编号由既有脚本分配，不由模型预定。
- 脚本负责摘要、版本、结构、编号和并发一致性；模型判断含义，人工核对分流。格式解析成功、摘要更新成功或文本命中都不证明需求含义未变。

## PG-17：内容修改及无法判断的措辞

| 输入 | 预期处理 | 人工关注 |
| --- | --- | --- |
| “把导出当前筛选结果改成导出全部数据。” | 说明导出范围发生变化，建议回到需求分析更正，再同步；不改 PRD、追溯或分析。 | 不能将“全部数据”视为润色。 |
| “删掉导出功能。” | 回交分析撤销对应条目；不在 PRD 直接删功能、废止编号或修改优先级。 | 生成侧没有分析结论写入权。 |
| “把‘用户可以导出’改成‘系统必须自动导出’。” | 说明主体、触发方式及义务变化，按内容修改回交。 | “措辞”这个请求标签不决定分流。 |
| 用户只说“把这里写得更强一点”，无法确定目标语义 | 说明可能改变约束强度，按内容修改处理；如需澄清，提供选项，不自行挑选新规则。 | 不把不确定性当作直接编辑许可。 |

交接建议可以引用原分析条目、旧规则、用户希望的变化及影响，但不能调用分析写入器、伪造分析修订或假称已完成回交接收。

## PG-18：纯排版及不改变含义的编辑

| 输入 | 预期处理 | 人工关注 |
| --- | --- | --- |
| “把业务规则标题加粗，修正明显错别字，不改变规则。” | 在保留稳定标记、正式编号、分析引用和分析含义的前提下保存排版编辑。 | 可见布局可变化，追溯身份不变。 |
| 把“用户可以导出当前筛选结果”润色为“用户可导出当前筛选结果” | 在确认确无含义变化后允许编辑。 | 不扩展数据范围、权限、触发条件或验收要求。 |
| 请求名义为排版，但候选把“当前筛选结果”改成“全部数据” | 按内容变化回交，不因请求名为“排版”就保存。 | 语义评审覆盖实际差异，不只读用户标签。 |

首次发布前，版本由 `0.N` 递增为 `0.(N+1)`；记录 `layout_edit`，更新信息视图和正文原始字节摘要。正式编号、映射、完整分析引用、来源摘要、标签、状态、引入版本及计数器保持，缺口身份和交接进度不变。既有遗留事项、不确定性标注不得顺带丢失。发布后的排版版本与不可变基线仍归阶段 6。

## 手工修改检测：本阶段局部检查

1. **未改稿**：实际正文与 `content_hash` 一致，不误报手工修改，不因只读查看而写事件或递增版本。
2. **只有排版变化**：检测摘要不符，实际比较旧稿和当前稿；核对无含义变化后才刷新摘要和信息，按排版编辑留痕。不能先重置摘要，再声称没有发现修改。
3. **内容性修改**：手工把“当前筛选结果”改为“全部数据”，或在非编号范围章节增加“支持跨租户导出”；应检出实际差异，提示转回分析，记录 `manual_edit_detected`，不反向覆盖分析，不静默吞掉用户原改动。
4. **无法判断**：旧稿不可取得、无法验证旧稿摘要，或措辞是否改变含义有疑问时，明确说明证据或语义不足，不把它当作无害排版。
5. **用户坚持保留**：只有实际收到坚持保留的回答后才处理；保留对应内容，标注【与分析不一致】，列入遗留事项，并保留检测事件及必要的处理说明。更新后的摘要与实际正文一致，但不能因此抹掉不一致或宣称可发布。
6. **没有坚持保留**：不提前注入未来回答。保持检测到的改动证据，给出回交建议；不自行选用“保留”“撤销”或分析结论。
7. **已有标注后再次修改**：仍检查摘要，既有【与分析不一致】及遗留事项不能因一次排版、重新生成或同步被无依据清除；只有分析真正覆盖相应变化后才另行核实处理。
8. **身份或定位结构损坏**：编号、引用、定位标记被删改时给出具体诊断；不通过重新分配编号或洗掉摘要掩盖结构问题。

本阶段验证校验器能诊断不一致及发布阻断依据；**不将 PG-19 完整场景记为通过**，不模拟阶段 6 的发布入口。

## 写入与失败边界

- 读取时先比较分析修订，待同步则明确说明，不能把编辑当作完成分析同步或偷偷前移 PRD 的分析基准。
- 当前阶段只处理已有未发布工作稿；已发布、已废弃及发布快照不能被编辑入口覆盖。
- 内容修改请求只给交接建议，不写正式 PRD 或分析。只读检查和只读查看也不授权业务写入。
- 保存前核对读时 PRD 版本、分析修订和实际文件；冲突拒写，重读后重新比较，不盲改基准数字重试。
- 候选校验失败保留候选与诊断，不改正式产物；中断和恢复复用现有一致性边界，事件不能重复追加。
- 生成、同步、排版、手工修改处理后都检查 `content_hash`；分析目录、`common` 及其他元数据块、其他需求和发布快照保持不变。

## 程序与模型验证计划

- 程序覆盖 PG-17/PG-18 的可执行边界、摘要一致性、身份保持、并发、恢复及上述手工修改局部分支；程序不能替代语义分流评审。
- 拟进行两组实际模型试跑：修改请求分流及纯排版；手工修改检测、回交及坚持保留。按编辑前 Skill 与新 Skill 分别运行，参考答案和预设后续回答不放入模型输入。
- 模型试跑使用本地隔离副本和现有工具；启动前由用户确认。保留真实对话、候选、响应、时间和产物，使用既有 Skill Creator 评审工具生成静态评审页。
- 记录内容性与排版性样本数量及正确分流数、版本和事件、编号及引用保持数、分析目录指纹；不自行设定未获认可的指标阈值。

阶段退出仍需当前源码回归、实际语义评审及用户明确认可；不安装、不评审发布、不公开上传业务资料，不自动提交、合并、打标签或推送。
