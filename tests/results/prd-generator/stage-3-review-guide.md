# 阶段 3 草稿试用评审指南

本文帮助用户按已认可参考核对实际模型产物，不是评审结论。程序检查、模型辅助核对和用户签核分开保存；当前最终人工试用未完成。

## 先看哪些产物

实际模型任务分两组，各有 `with_skill` 和 `without_skill` 对照。对照仍提供相同确定性脚本，用于区分 Skill 流程与参考的作用，不是无工具对照；每组每配置仅一次运行，不能据此宣称统计显著的提升。

- 高低压：`REQ-2026-001`，核对一份风险草稿。
- 任务管理：`REQ-2026-002`～`REQ-2026-006`，分别核对筛选、删除、状态、导出、通知五份草稿，不把删除需求当作全文。
- 每份应有首次 `0.1` 与重复 `0.2` 的真实响应和候选。版本、生成信息和记录变化合法；需求正文、正式编号、映射及来源摘要不应漂移。
- 当前六份业务分析均未就绪。程序 `pass` 只是结构及一致性结果，不把它们升级成正式基线。

评审页由 Skill Creator 自带 `eval-viewer/generate_review.py` 生成；实际输出归档于 `stage-3-model-review/`，原始试跑保存在 `workspace-sandbox/prd-generator/stage-3-model/iteration-1/`。未完成的运行不能用历史或合成输出代替。

## 业务忠实性核对

### 高低压

1. 读取分类、两个页签、按勾选生成表的范围不丢失；组合含义、高低压联动和表内容仍明确未确定。
2. `AC-1` 只是两个页签职责的验收，不扩为完整输出算法；`AC-2`、`FLOW-1` 仍同时为推断和待确认。
3. 核心问题、边界、研发确认和待设计事项列入遗留。缺视觉与技术资料不被补成现有界面或已核验能力。
4. 没有擅自引入二态全排列、笛卡尔积、一一配对、互锁规则、具体字段、数量上限、分页、导出或批处理。

### 任务管理

1. 五个需求的独立边界保持；原文组织拆分不变成用户明确排除其他功能。
2. 删除权限的两项冲突陈述都保留“非最终授权规则”，没有选择或合并成最终权限；旧逻辑资料未提供的限定不丢失。
3. 不补跨页选择、软/硬删除、运行中处理、恢复和批量失败规则；删除验收和流程仍带推断与待确认。
4. 筛选不补字段、匹配方式和性能阈值；状态不补状态机、轮询频率或故障根因。
5. 导出不裁决“超过1000条”的冲突，不补对象、字段、格式和权限；通知不默认渠道、接收人或触发结果。
6. “尽量不影响仿真引擎”和“尽快上线”不强化为绝对禁改或明确日期；界面依赖不等于已有视觉证据。

## 程序结果怎么看

- 正式条目的完整引用、稳定来源摘要、文档信息、正文摘要、标签及适用遗留块由现有校验器检查；原始计数保存到模型程序核对 JSON。
- 程序没有证明“自然语言表达完全忠实”“缺口确实必要”或“引用内容足够补足缺口”。这些仍按上文人工核对。
- 合成 CLI 覆盖 14 个条目，其中阶段 3 首次完整场景为 12 个，PG-04/05 仅验证生成局部；发布拒绝仍归阶段 6。合成正文不算实际模型自主输出。
- 来源缺省的降级必须保留独立门禁：有效条目仍须来源，历史依据过期仍须 `stale/not_ready`，不能借缺清单变为正式草稿。

## 指标评审

保留需求性条目总数及有效追溯数、需标注总数及正确保留数、撤销样本数、重复生成编号和正文比较结果。程序口径与人工语义判断分别记。

无适用样本记“不适用”，不是100%；没有同步、修改分流、真实发布尝试，不给这些能力记满分。规格已有“全部追溯”、禁止撤销进入有效章节、不得补事实等硬规则不因阈值未定而放宽。

首轮试用后由用户决定其余指标的阈值或后续确定方式；当前没有擅自设置阈值。认可参考、认可本轮草稿、决定阈值和批准发布是不同决定，不互相代替。
