# 合成需求处理结果

本次使用指定旧版 `prd-generator`，四份合成需求分别处理。该版本支持首稿和分析驱动的增量同步，但**不支持编辑、编辑分流或将手工编辑纳入工作稿的处理**；不能借同步写入器绕开这一边界。以下均未保存 PRD 改动，也未调用分析写入器。

| 场景 | 结果 | 判断与后续 |
| --- | --- | --- |
| content-request | 拒绝编辑；未保存 | 从导出当前筛选结果改为导出全部数据是需求内容变更。建议由用户决定是否交回 Requirement Analyst 做变更分析，本次未执行分析或改写。 |
| ambiguous-request | 拒绝编辑；未保存 | “用户可以”改为“系统必须自动”不仅是润色，还改变触发方式和约束程度。建议交回 Requirement Analyst 澄清，本次未执行分析或改写。 |
| layout-request | 拒绝编辑；未保存 | 即使提出不改变规则，该旧版也未实现编辑或编辑分流，未将“用户可以”替换为“用户可”。 |
| manual-layout | 未确认仅此一处改动；拒绝后续编辑处理，未保存 | 当前稿中确实能看到功能项的 `**用户可以**`。本次没有该独立需求手工修改前的可信正文基线，不能据此确认整份文档只有这一处排版改动；同步检查比较的是分析来源，不证明正文没有其他手工改动。旧版不支持手工编辑后的编辑处理，因此保持当前工作稿原状。 |

## 检查和警告

对四份已有工作稿分别运行了只读 `check_sync.py`，四次均返回 `status: warning`、`allowed: true`、`pending: false`，分析修订和稿件基准均为 1，版本为 0.1，已有功能项来源比较为 unchanged，无新增来源。脚本进程均以 1 退出，这是警告状态的三态退出码，不是声称检查完全无警告。检查结果不构成对正文手工修改的完整核验，也不构成人工评审。

每份稿件都有同一条警告：辅助分析事件 `analysis/analysis-events.jsonl` 不可用，只能按条目比较生成变更摘要，不能推断变更原因。每份都标示未覆盖 `value_assessment`、`technical_feasibility`、`impact_analysis`。完整逐次 JSON、stderr 和运行命令保存在同级 `artifacts/`。

没有生成候选、执行写入或同步、变更分析与元数据、发布、安装，或进行 Git 操作；也没有重试修正。`manual-layout` 原有手工加粗在复制的工作区中保留，不能将其算作本次保存的变更。机器检查和 AI 判断不代替人工审查。
