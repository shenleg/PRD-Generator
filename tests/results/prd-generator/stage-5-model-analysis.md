## 真实质量问题与修复

手改组首候选删除了“无适用遗留项”，并添加真实不一致遗留项。原写入器把这个已失效的空集合提示也当作必须原样保留的正文，两份首候选均被拒绝。模型各修正一次，保留该提示并在说明中解释其不再适用后，原工具才保存成功。

因此，原实际最终稿虽然通过结构与归属检查，仍存在文档质量问题。不能把程序 `warning` 或最初六条断言通过等同于全部语义达标。

修复后的保存器只允许并移除遗留章内独立的空集合提示；真实遗留说明和其他业务内容继续受保护。新增回归同时覆盖：允许模型正确删除提示、候选仍带提示时最终移除、不得借机删除实质遗留文本。使用原始首候选的当前源码重放已单独留证；它不是新的模型调用，也不改写原失败或模型最终稿。

## 客观评分与局限

最终评审目录 `stage-5-model-review/final-03/` 对原实际产物评分：

- 修改请求：新 Skill `6/6`；旧 Skill `3/6`。
- 手工内容：新 Skill `6/7`；旧 Skill `2/7`。新增第七条检查“新增遗留后不再声称无遗留项”，来源于本次真实发现，未伪装为预先盲测。
- 旧 Skill 的拒绝是遵守原边界，不是程序崩溃；未实现的编辑不能计为完成。
- 分析目录和身份保持等断言是保护边界，不足以区分自然语言分流质量。只检查“不写”也无法证明回交理由正确，仍需人工读实际说明和原分析。
- 每配置每组只有一个样本，不据此估计稳定通过率，不把跨两种任务的统计当作重复实验。

官方 Skill Creator 汇总和静态评审工具用于生成页面。时间与 token 保留工具通知原值；有首轮/后续轮及调度暂停，不据此声称效率或费用改善。

## 运行限制与调度记录

- 模型写入在各自私有 worktree 的 `stage-5-trial` 中，主线程归档至各 run 的 `completed-trial`；共享初始输入保持不变。不存在权限拒绝后的绕过写入。
- 主线程误把并行工具返回顺序当作任务顺序，曾向新修改请求组发送错误的组名及等待说明。代理指出原任务限制，未读取另一组；主线程撤回错误要求后，代理继续原始四场景。首轮暂停产物和报告保存在 `coordination-paused-trial`，不掩盖为首次无中断成功。
- 手工内容组的 `first-round-trial` 在发送模拟回答前归档，`scripted-answer.json` 明确记录模拟属性及“实际提问后提供”。不存在首轮提前注入“坚持保留”。
- 旧修改请求组称“缺少可信正文基线”，但新建输入的追溯实际含 `content_baseline`。准确结论是旧工具没有读取/核验该兼容扩展，不能将模型原话当作工作区真实缺字段的证据；原报告保持原样。
- 新 Skill 所谓“没有未处理手改”只表示摘要已与已处理正文一致，不表示与分析一致；原位置和遗留项仍标注不一致，校验仍明确不得发布。
