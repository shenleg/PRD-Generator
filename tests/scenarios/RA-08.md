# RA-08：结束与追问上限

验证目标：尊重结束，保留核心缺口。

## 输入与预设回答

分支 A：RA-05 后续用户说“先这样吧，直接出结果。”

分支 B：第一样例试跑时配置业务追问上限为 1 轮。首轮后用户说“这轮先不回答。”；模型若请求继续或结束，选择“结束”。该控制确认计入发生提问的总轮数，单独注明不是新增业务追问。

## 核对清单

- [ ] 用户结束后立即出当前结果，不继续询问业务问题。
- [ ] completed 与 not_ready 可以同时成立；open P0 不自动关闭。
- [ ] 达上限时询问继续或结束，不替用户接受风险或把未回答 P0 全转假设。
- [ ] 报告醒目标注仍未解决的 P0、无法形成的核心验收条件。
- [ ] 需研发确认事项保留，不能为了结束而编造现有能力。

依据：规格 6.5 及第二样例第 4.1 节的结束回答。
