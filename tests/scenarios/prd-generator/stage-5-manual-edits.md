# 阶段 5：手工修改检测的局部检查

本文覆盖 PG-19 在阶段 5 的前置能力，**不是 PG-19 的首次完整验收**；完整发布拒绝链仍归阶段 6。状态：局部程序、实际模型和修复后重放通过，用户已认可本轮表达；证据见 `tests/results/prd-generator/stage-5-final-approval.json`。不认领阶段6完整场景。

## 输入与前置状态

每个分支采用独立的合成需求及合法未发布工作稿，保存生成时正文、摘要、元数据、追溯、缺口、事件和分析目录指纹。部分分支故意模拟旧追溯无正文比较基准。参考见 `tests/expected/prd-generator/stage-5.review-draft.md`，认可记录见 `tests/results/prd-generator/stage-5-approval.json`。

## 分支和用户回答

| 分支 | 实际修改或请求 | 预期 |
| --- | --- | --- |
| 未改稿 | 只读查看 | 不误报，不写事件或版本。 |
| 纯排版 | 手工加粗标题或修正错别字 | 检测摘要差异，实际比较并核实含义后按排版处理；不直接洗掉摘要。 |
| 正式条目内容变化 | 把导出范围从当前筛选改为全部数据 | 提示回交分析，记录 `manual_edit_detected`，不反向覆盖分析。 |
| 非编号章节变化 | 在范围中手工加入跨租户导出 | 同样检测，不能只比较正式条目块。 |
| 缺旧稿 | 正文已变化且无可验证的旧字节 | 明确证据不足，不自动当排版，不伪造旧正文或精确 diff。 |
| 用户坚持保留 | 仅在实际被询问如何处理后回答“保留我改的内容，接受不一致标记” | 对应内容标【与分析不一致】，列入遗留事项，事件保留；摘要更新不解除发布阻断。 |
| 用户未坚持 | 检测后不提供未来回答 | 不提前执行坚持保留分支，不静默撤销用户原改动。 |
| 定位结构损坏 | 删除或变更正式编号、分析引用或标记 | 具体诊断并拒绝以重编号或更新摘要掩盖结构破坏。 |
| 并发变化 | 比较后另行变更版本、分析或正文 | 保存拒绝，保留候选和证据，重读后再判断。 |

预设回答与参考答案分离：模型只在实际走到对应问题时接收用户回答，不能在首轮材料中看到“将来坚持保留”。

## 留证与边界

- 保存手改前后正文、可验证旧基准、实际差异、对话、候选、脚本响应、最终文件及指纹。
- 分开登记摘要检测、实际差异比较、语义判断、用户坚持和最终保存，不能用一个成功状态代替全部步骤。
- 验证校验器报告不一致及发布阻断依据，但不声称调用了尚未实现的发布 API。
- 手改是模拟输入，生成侧处理阶段仍须保持 `analysis/`、`common`、其他需求及发布快照不变。
- 实现入口、正文基准和不一致遗留项定位规则须先经过协议评审；本剧本不自行定义或批准新格式。
