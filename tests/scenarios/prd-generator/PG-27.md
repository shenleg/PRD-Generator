# PG-27：正式安装后，生成和同步不写分析

本剧本定义阶段 7 的首次完整验收。依据生成规格 §9.5、§9.10、§10、§11.2、§12.1，分析规格 §10。不把阶段 2 的缺口夹具或显式加载提示词试跑当作正式联调结果。

## 输入与前置状态

- 在隔离项目并列安装当前两个生产 Skill；安装目录不含 `tests/`、最小消费者或沙盒。新会话发现技能，记录宿主版本、当次生产载荷指纹及实际 Skill 工具调用。
- 工程联调用合成需求：分析侧创建单个需求，保留至少一条可追溯的有效分析条目和一处尚未得到答案、但项目模板要求说明的内容。不直接构造正式缺口文件。真实需求试用另行记录。
- 评审参考为 `tests/expected/prd-generator/stage-7.review-draft.md`。不给被测模型参考要点、预设后续回答或旧黄金输出。

## 逐轮操作

1. 自然语言要求分析需求，观察安装后的 `requirement-analyst` 自动触发。若模型实际追问，操作者才依合成输入给出已知信息；对尚不确定的模板内容不编答案。分析侧用正式更新器创建并保存。
2. 切换到安装后的 `prd-generator` 生成 PRD。至少一次从用户直接调用 `/prd-generator` 进入，另用不含调用名的普通提示实际观察生成侧自动触发；分别记录，不以同一次显式提示冒充两种方式。首稿通过正式写入器生成 `open` 缺口、占位和追溯；对生成前后的 `analysis/` 全部业务文件作指纹比较。
3. 用户要求接收生成器实际登记的缺口。切回分析 Skill，经正式更新器登记唯一的接收问题；缺口仅把 `status` 改成 `handed_over`。本轮新增分析内容单记，不混入生成侧指纹断言。未得到答案前不得关闭缺口。
4. 在分析 Skill 实际询问所缺信息后，由操作者给出明确标记的合成答复；正式更新流程保存分析并提高修订号。只说已答复或只改问题状态不能作为内容补足的依据。
5. 用自然语言在同一对话继续同步，如“按刚才补充的内容更新文档”。观察是否自动调用生成侧并承接同一需求，不重新猜项目或业务规则。经核实后由生成侧同步关闭缺口并替换或移去占位；比较同步前后同一范围的分析文件指纹。保存实际补丁、诊断、最终分析、PRD、追溯、事件及两段指纹。

## 允许和禁止的文件变化

- 生成和同步两段均只允许变更预期的 `prd/` 业务产物、`requirement.json` 的 `prd` 块和独立候选目录；不得改动 `analysis/` 下任何业务文件、输入和 `common` 块。目录树比较同时检查增删和字节差异，锁与私有事务记录单独列明。
- 分析接收补充段允许正常分析更新；对 `prd/` 的变更仅限经规格允许的目标缺口状态标记。PRD 正文、追溯、事件、其他缺口内容和快照必须保持。
- 同步中未被影响的需求条目及既有编号保持。仅输出成功文案、文件缺失、非正式 Skill 路径或证据无法归属时，不把场景判为通过。
