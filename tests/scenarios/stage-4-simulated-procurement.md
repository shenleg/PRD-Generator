# 阶段 4 模拟业务试用：办公采购申请批量撤回

## 性质与目标

用户要求构造一个贴近实际的需求进行试用。原文及业务回答均由助手模拟，不来自真实组织，不作为用户产品决定。2026-11-16用户另行明确批准以本案例满足本次阶段4需求试用验收条件；该批准不改变案例来源、业务就绪度及尚未验证的集成项。当前验收记录见 `tests/results/stage-4-acceptance.md`。

最初计划由独立分析会话保存补丁，但该会话报告隔离限制、未成功保存；用户随后明确选择“主会话直接试用”。实际由主会话读取当前 Skill、多轮分析模拟原文并按本轮实际问题给出相应模拟回答，再原样调用更新器和消费者。这是主会话模拟，不是独立盲测；与既有机械场景相比，增加了贴近业务的逐轮分析与实际补丁留痕，不声称独立模型行为评测。执行方式调整见试用目录的 driver/execution-adjustment.json。

## 输入

`tests/fixtures/stage-4-procurement-withdrawal.md`。主会话同时是模拟场景作者，知道答案库，因此不具备盲测独立性；保存的每轮补丁只使用当轮已发生的回答，不提前把未来回答写成已确认业务规则。

## 预设回答

模拟答案库在 `workspace-sandbox/stage-4/simulated-trial-01/driver/scenario.json`。每轮只选实际问到的语义；独立保存给出的原话及其 topic，不把未发生的答案混进分析。结束按原话输入，不用“结束”冒充业务回答或风险接受。

不强行要求最终 ready_for_document。若核心未答，保留 P0/not_ready，只生成风险初稿；若因结构错误修复，只回传真实诊断，不追加业务答案。

## 核对清单

- [ ] 原文事实有来源定位；状态冲突明确登记而非自行裁决。
- [ ] 每轮 1～3 个独立决策，实际回答前不预先关闭问题。
- [ ] 旧候选规则在裁决后不与现行互斥规则同时 active。
- [ ] 已答语义不重复问，部分回答可继续澄清剩余部分。
- [ ] 并发、权限及审批历史作为业务边界；实现机制登记 ask_dev，不编造技术能力。
- [ ] 所有正式写入经真实更新器 CLI，保存实际响应及快照。
- [ ] 结束时保留实际遗留问题与完成清单，不因校验 pass 强行就绪。
- [ ] 实际消费者保留标签、映射、风险和研发事项，不修改 analysis/。
- [ ] 模拟性质、显式源码加载方式和未验证的真实集成边界清楚记录。
