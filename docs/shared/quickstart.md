# 快速上手：从一句需求到可追溯的 PRD

适合手上已有需求想法、会议纪要或旧文档，想先把规则和验收条件谈清楚，再交给研发的团队。`requirement-analyst` 负责分析、追问和保存结论，`prd-generator` 用已保存的分析写 PRD；改业务规则时，先更新分析，再同步文档。

## 1. 安装并打开项目

1. 准备 Claude Code、Python 3.10+ 和 `uv`。本指南以已经验证的本地 Linux 环境为例。`uv` 用于给脚本准备依赖，不是 Skill 安装器。
2. 获取本仓库，按[双 Skill 安装说明](../prd-generator/installation.md#安装到新项目或隔离试用项目)把两个完整生产目录放进**要使用的项目**的 `.claude/skills/`。第一次试用可以另选一个空目录，不用把测试、沙盒或最小消费者一起复制过去。
3. 在**目标项目目录**开启新的 Claude Code 会话。需求分析用自然语言触发，没有 `/requirement-analyst`；生成可以直接用 `/prd-generator`，也可以说“根据已保存的分析生成 PRD”。

先用下面的合成场景练习。换成团队的真实需求时，只提供获准交给当前模型和环境处理的资料。

## 2. 动手示例：撤销会议室预约

### 先分析并保存

在新会话发送：

```text
请分析并保存这个需求到 ./workspace，项目编号用 room-booking-demo，需求编号由脚本分配。
我们希望员工能撤销本人提交的会议室预约。会议开始后不能撤销，撤销成功后该时段重新开放预约。
先告诉我你理解的范围和最重要的待确认问题；不要先生成 PRD。
```

按模型实际问到的问题逐轮回答。例如问到能否代撤、重复撤销及是否通知，可以回答：

```text
本期不允许代撤。不发撤销通知。重复撤销只提示“已撤销”，不再改动预约或时段状态。
请保存本轮分析结果，告诉我需求目录、当前就绪度和仍未确认的事项。
```

这些是练习用答复，不是 Skill 的默认业务规则。还有影响范围或验收的未知时，继续回答，或者明确保留待确认；不要要求模型把没定的事写成事实。看到已保存的**需求编号和目录**再进入下一步，不把聊天中的总结当成已保存的分析。

### 用同一份分析生成工作稿

在同一会话发送：

```text
/prd-generator 根据刚才已保存的分析生成可追溯的 PRD 工作稿。告诉我草稿类型、遗留事项和文件位置，不要提审或发布。
```

如果换了会话，注明上一步返回的实际需求目录。核对工作稿是否保留“只能撤销本人预约、会议开始后不可撤销、撤销成功后释放时段”，以及仍未确定的事项；不要把未确定的内容写成已经批准的验收条件。若提示没有可用分析，先回上一步；有遗留问题不意味着必须编出正式需求或强行定稿。

### 试一次业务规则变更

仍对同一需求，先发送：

```text
请先更新同一需求的分析：必须在会议开始前至少 10 分钟才允许撤销，恰好提前 10 分钟仍可撤销。其他规则不变。先保存分析，不直接改 PRD。
```

等提示分析已保存，再发送：

```text
/prd-generator 把该需求的最新分析同步到现有 PRD。告诉我改了哪些规则和验收条件，哪些没有改。不提审、不发布。
```

核对提前时间的边界是否反映在规则和验收条件中，原有本人权限、时段释放和其他无关规则是否仍保留。若出现 PRD 缺口或待确认事项，先回到需求分析补足，再同步；不能只改状态当作内容已补足。

## 3. 去哪里看结果

以下以示例项目为例，`<需求编号>` 以 Skill 实际返回的目录名为准：

```text
workspace/projects/room-booking-demo/requirements/<需求编号>/
├── analysis/analysis-result.json  已保存的结构化分析，生成侧据此写文档
├── prd/prd.md                     发给研发或测试看的工作稿
└── prd/prd-trace.json             正式条目对应的分析来源
```

第一次交给同事时，先发 `prd.md`，提醒对方看遗留事项。需要复核依据时，再附追溯文件及同一需求的分析。草稿或校验通过不是产品经理的发布批准。

**想先看实际成品？** 仓库已保存一轮真实文档需求试用：[首稿 0.1](../../workspace-sandbox/prd-generator/stage-7-real-trial/first-draft/prd/prd.md) → [变更同步后的 0.2](../../workspace-sandbox/prd-generator/stage-7-real-trial/synced-draft/prd/prd.md)。这是另一项需求，不是上述练习的标准答案；两版都是工作稿，不是已发布文档。

如果找不到 Skill，先核对是否在目标项目开启了新会话、两个目录是否完整；若 Python 依赖缺失或保存遭权限拒绝，先处理[安装依赖](../prd-generator/installation.md#依赖和验证)或按团队规则授权对应操作，不要手改结构化产物来绕过失败。
